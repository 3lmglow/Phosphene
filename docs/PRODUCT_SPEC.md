# 产品与规则

本文说明当前版本中用户能够看到和依赖的产品行为。部署方式见 [部署与运维](DEPLOYMENT.md)，AI 接口参数见 [MCP 连接与工具](MCP.md)。

## 产品边界

每套 Phosphene 服务一位用户和一位 AI：

- 用户登录网站，完成任务、提交证据、查看积分并兑换奖励。
- AI 通过 MCP 创建和管理任务、审核提交、管理奖励。
- 系统负责重复任务、逾期、积分、连击、成就和事件通知。
- 显示称呼可以自定义；内部角色仍使用 `user`、`AI` 和 `system`。

Phosphene 不提供公开注册、多人空间或组织权限。

## 任务

### 类型

| 类型 | 用途 | 是否可每日重复 |
| --- | --- | --- |
| `daily` | 日常约定与习惯 | 可以 |
| `challenge` | 有明确截止时间的挑战 | 不可以 |
| `surprise` | 下次访问或指定时间揭晓的惊喜 | 不可以 |

每日重复任务由一条系列规则和每天的独立任务组成。暂停系列时，当天尚未提交的任务会离开待办；已提交、已完成和历史任务不受影响。当天截止前恢复时，当天任务会重新出现。

### 状态

| 状态 | 含义 |
| --- | --- |
| `pending` | 等待用户完成 |
| `submitted` | 已提交，等待 AI 审核 |
| `completed` | 已完成并结算 |
| `failed` | 被 AI 判定失败 |
| `expired` | 超过截止时间 |
| `cancelled` | 已取消，不结算 |

### 确认方式

- `self`：用户确认后立即完成。
- `ai_review`：用户先提交，AI 批准后完成。

用户在截止前提交、AI 稍后才批准时，完成日期仍按用户实际提交的当地日期计算。

AI 驳回时必须给出理由。任务会回到待完成状态，详情页保留驳回理由与上次文字，用户可以修改后再次提交。

### 证据

现有任务支持：

- 无证据
- 文字
- 图片
- 文字或图片
- 文字和图片

AI 新建任务时使用无证据、文字或文字和图片。这样需要审核的图片任务同时具有可读文字。既有的纯图片任务仍可继续完成。

每次提交都会成为独立记录，保留文字、净化后的图片、提交时间、审核状态和驳回理由。

## 图片处理

- 每次最多 4 张，单张最多 10 MB
- 支持 JPEG、PNG 与 WebP
- 检查真实文件格式与像素数量
- 按正确方向重新编码为 WebP，并移除 EXIF 与 GPS
- 保存净化后的完整图片和较小的 AI 审核预览
- 图片位于私有数据目录，不通过静态 URL 公开

## 积分

### 任务结算

| 难度 | 倍率 |
| --- | --- |
| easy | ×1 |
| medium | ×2 |
| hard | ×3 |

任务积分 = 基础积分 × 难度倍率。

任务失败或逾期时扣除最终任务积分的 50%，但余额不会因此低于 0。系统自动逾期属于任务规则；AI 主动判定失败则服从用户设置的惩罚暂停和每日 AI 扣分上限。

### 积分账本

任务奖励、连击奖励、任务扣分、兑换、AI 调整与校正都会写入积分账本。历史流水不被修改；需要纠正时新增一条 correction。

每次结算、兑换和 AI 写操作都有幂等保护。网络重试不会重复发分、扣分或创建兑换。

### 用户边界

用户可以设置：

- 是否暂停 AI 主动惩罚
- AI 每日最多主动扣除多少积分
- 0–5 的惩罚强度偏好
- 允许与禁止的内容

惩罚强度是提供给 AI 理解关系边界的偏好，不会改变服务端固定的任务扣分公式。AI 不能修改这些设置。

## 连击与统计

自然日按用户设置的时区计算。当天至少完成一项任务，就算一个有效完成日并延续连击。

每天最多获得一次连击奖励：

| 连击天数 | 当日奖励 |
| --- | --- |
| 第 1 天 | 0 |
| 第 2–5 天 | +1 |
| 第 6–7 天 | +2 |
| 第 8 天起 | +3 |

Phosphene 记录：

- 当前余额、累计获得、累计消费和累计扣除
- 当前连击与最长连击
- 总坚持天数与总完成任务数
- 按任务类型和难度统计的完成数量
- 今日完成状态、待完成、待审核和待履行数量

“轨迹”页的活跃日历显示最近一年每天完成了多少项任务，颜色越深完成得越多；日期同样按用户设置的时区划分。

AI 延迟审核造成历史日期补入时，系统会重新计算受影响的连击，并通过新的校正流水补足差额。

## 奖励与兑换

用户在网站兑换，AI 不能替用户消费。

兑换发生时，系统在同一事务中读取当前价格、检查余额、创建兑换并扣除积分。兑换先进入待履行状态；AI 真正兑现后再标记为已履行，并可以附一段留言。用户会在兑换记录和历史时间线中看到履行时间与留言原文。

AI 可以创建和修改自定义奖励，也可以归档或恢复奖励。归档只会把奖励从当前兑换列表中移除，不会破坏历史兑换。

新实例包含两项可修改的示例奖励：

- 指定 AI 写东西：15 分
- “AI 听你的”券：20 分

## 成就

内置成就覆盖：

- 第一次完成任务、第一次完成 hard/challenge/surprise
- 3、7、14、30、100 天连击
- 7、30、100、365 个坚持日
- 10、50、100、500 个完成任务
- 累计获得 100、500、1000、5000 分
- 第一次兑换与完成 10 次兑换

成就在相关业务结算时自动检查，不需要 AI 单独授予。

## 完成通知

用户提交待审核任务、任务完成或创建兑换时，系统会保存领域事件。AI 可以通过 Webhook 接收推送，也可以定时读取事件游标。

事件只包含识别任务或兑换所需的结构化事实；AI 再通过 MCP 查询最新正文、证据和状态。这样既避免在通知请求中复制私人内容，也避免根据延迟到达的旧快照做决定。

接入方式见 [完成通知](WEBHOOKS.md)。

## 权限

| 能力 | 用户 | AI | 系统 |
| --- | --- | --- | --- |
| 查看与提交任务 | 是 | 查询与管理 | 生成重复实例 |
| 审核提交 | — | 是 | — |
| 修改用户边界与密码 | 是 | 否 | 否 |
| 兑换奖励 | 是 | 否 | — |
| 履行奖励 | — | 是 | — |
| 任务和连击结算 | — | 发起部分动作 | 是 |
| 配置完成通知和备份 | 是 | 否 | 执行 |

所有写操作都会进入审计历史。
