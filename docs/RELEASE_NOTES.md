# 版本更新说明

## v1.1.0 · 内存修复、ChatGPT / Claude 官方应用连接与新的部署方式

本版本修复了 v1.0.1 及更早版本中会随运行时间持续增长的内存问题，**建议所有用户更新**。同时新增 OAuth 授权连接、任务逾期事件、活跃日历和若干界面改进，并重写了部署文档。

云平台 Zeabur 已宣布停止运营（[Zeabur 官方公告](https://zeabur.com/zh-CN/blogs/zeabur-is-shutting-down)），共享集群自 12 月 1 日起暂停。Phosphene 本身不受影响，正在使用 Zeabur 的用户可按照 [从 Zeabur 迁移](MIGRATE_FROM_ZEABUR.md) 迁移到其他部署方式。

### 内存问题修复

- **现象：**即使没有使用，容器内存也会持续上涨，1–2 小时内可达到约 600 MiB，随后被系统终止并自动重启，如此循环，还可能影响同一台服务器上的其他服务。
- **原因：**数据库组件 `@libsql/client` 0.17.4 每开启一次写事务，都会遗留一个不再释放的连接，每次约 160 KiB。完成通知的后台任务每 2 秒检查一次待发送的通知，即使未开启通知也会开启事务，内存因此持续增长。
- **修复：**
  - 数据库组件升级到 0.18.0，改为复用连接；
  - 后台任务确认存在需要发送的通知后才开启事务；
  - 读取任务时，仅在需要揭晓惊喜任务时写入数据库。
- **验证：**在测试服务器上连续发起约 13,500 次写入数据库的请求，内存稳定在 120–130 MiB。按旧版本的增长速度，约 2,500 次写事务即会达到 512 MiB。

### 并发写入不再失败

所有写入现在在服务内按顺序排队执行。此前用户提交、AI 审核和后台任务同时写入时，可能有一方收到 `SQLITE_BUSY: database is locked` 并需要重试；现在会依次完成。

### 支持 ChatGPT、Claude 官方应用连接

此前 Phosphene 只支持 AI Token，无法在 ChatGPT、Claude 官方应用中通过自定义连接器使用。本版本新增 OAuth 授权：在应用中添加自定义连接器，地址填写 `https://你的地址/mcp`，在跳转到的 Phosphene 授权页中点击“允许连接”即可完成连接。该流程已在 ChatGPT（Plus 账号）中实测通过。

- “设置 → AI 连接”中可以查看已授权的应用及其最近使用时间，并随时撤销授权。
- 通过授权连接的应用与 AI Token 拥有相同权限。原有 AI Token 继续有效，Claude Code、Codex 等客户端无需修改配置。
- 连接地址需要使用域名，ChatGPT 不接受 IP 地址形式的服务器地址。自己的服务器没有域名时，可以使用免费的 `sslip.io`，见 [部署与运维](DEPLOYMENT.md#连接-chatgptclaude-等应用)。

详细说明见 [MCP 连接与工具](MCP.md#claudechatgpt-等应用)。

### 任务逾期事件

任务超过截止时间、被系统判定逾期时，会产生 `task.expired` 事件，其中包含原截止时间和实际扣除的积分。已配置 Webhook 的实例默认推送该事件，事件轮询同样可以读取。

### 界面改进

- 网页中的时间、首页问候语和日期，均按“设置 → 称呼与时间”中选择的时区显示。
- AI 履行兑换时填写的留言，会显示在兑换记录和历史时间线中。
- “轨迹”页新增最近一年的活跃日历，颜色越深表示当天完成的任务越多。
- 调大了全站的小字号；调整首页数据卡布局，窄屏下也显示“总坚持天数”；下拉框与确认框改为与整体一致的样式；弹窗支持 Esc 关闭，并改进了键盘焦点。

### 部署文档

- 推荐先 fork 仓库，使用自己 fork 的 GitHub Actions 构建镜像后再部署，更新时机由用户自行掌握。
- 新增以 Sealos 为例的容器平台步骤，包括中国大陆可用区通过南京大学镜像站拉取镜像的方法。
- 自己的服务器使用 Docker Compose：
  - 内置可选的 Caddy，自动申请并续期 HTTPS 证书，没有域名时也可以通过 `https://服务器IP` 访问；
  - 默认为 Phosphene 设置 512 MiB 内存上限；
  - 建议设置 `PHOSPHENE_SETUP_TOKEN`。
- 新增 [从 Zeabur 迁移](MIGRATE_FROM_ZEABUR.md)，补充镜像拉取失败、HTTPS 和备份的说明。
- 删除 Zeabur 模板，以及仅用于启动日志的 `ZEABUR_WEB_URL` 和 `PUBLIC_URL`。旧部署中残留的这两个变量会被忽略。

### 依赖更新

MCP SDK 更新到 1.32.1，Express 更新到 5.3.0，Multer 更新到 2.4.0，Sharp 更新到 0.35.5，并更新多项间接依赖，修复依赖审计报告的 25 项安全通告（1 项严重、10 项高危），其中大多仅在登录后才能触及。开发工具 vitest 与 React 插件同步升级，开发依赖的安全通告已全部清零。

### 更新建议与已有数据

本版本会在启动时自动升级数据库：新增授权连接所需的表，并重建事件表。更新前请先在“设置 → 数据与备份”中导出一份 ZIP；更新后如需回到旧版本，请使用更新前的 ZIP 或卷快照恢复。本版本不新增必填环境变量。

- **使用自己 fork 构建镜像：**在 fork 首页点击 **Sync fork**，等待 Actions 构建完成后重新部署。
- **使用 `ghcr.io/3lmglow/phosphene:latest`：**照常重新部署即可，也建议借此改用自己 fork 构建的镜像。自本版本起，`latest` 只在发布正式版本时更新。
- **使用 Docker Compose 从源码构建：**执行 `git pull --ff-only` 后，照常运行 `docker compose up -d --build`，数据卷保持不变。

请注意以下两项行为变化：

- 新版 Compose 默认只在本机的 `127.0.0.1:8080` 提供 HTTP。此前直接通过 `http://服务器IP:8080` 访问，或从其他容器转发到该端口的，请在 `.env` 中加入 `PHOSPHENE_BIND=0.0.0.0`，或改用文档中的 Caddy 与面板反向代理。
- 已配置 Webhook 的实例，更新后会开始收到 `task.expired`。接收端遇到无法识别的事件类型时跳过即可。

### 感谢反馈

感谢 **[@7k777](https://github.com/7k777)** 在 [Issue #1](https://github.com/3lmglow/Phosphene/issues/1) 中详细记录了内存持续增长与 OOM 的现象，并定位到根因：旧版数据库组件的连接生命周期，以及空闲时仍在开启事务的通知轮询。ta 还提供了隔离复现与修复思路。本版本的内存修复正是基于这份分析完成的。

## v1.0.1 · 密码设置校验与可选密保找回

本次功能更新面向首次设置密码的用户，以及希望增加忘记密码找回方式的用户。已经能正常登录、也不需要密保的用户，不必仅为这些功能更新；本版本另包含一项依赖安全修复，可在日常维护时一并更新。

### 密码设置有什么变化

- 首次设置和“设置 → 登录安全”中的新密码，只支持大小写英文字母、数字和半角符号，不允许空格、中文、全角符号、换行或其他不可见字符。
- 保留 10–256 个字符的长度要求。可以只用字母、只用数字、只用半角符号，也可以任意组合，不要求同时包含各类字符。
- 两个页面均提供规则说明和中文错误提示。输入不符合要求时，不会继续设置或提交修改密码请求；用户可以修改原输入后再试。
- 服务端执行相同校验，直接通过接口设置密码时也适用。系统不会自动删除、替换或转换密码字符。

设置密码时请使用英文输入法，例如使用 `!` 而不是 `！`。详细处理方式见 [密码与登录问题](TROUBLESHOOTING.md#网站登录与写操作)。

### 可选的密保找回

- 首次设置密码后，可以填写自己的密保问题和答案，也可以直接跳过。
- 问题和答案自由填写，中文、名字、日期或简短答案都可以，不设复杂度要求。答案区分大小写，忽略首尾空格。
- 密保答案使用普通文本框，输入时可以直接核对内容，并使用中文输入法；登录密码仍使用隐藏输入。
- 登录页新增“忘记密码？”入口。答案正确后，可以设置新密码；原有登录会话会退出，任务、积分和 AI Token 保持不变。
- 已有用户可以在“设置 → 登录安全”中补设、修改或停用密保，操作时需要确认当前密码。
- 问题会显示在找回页，答案只保存 Argon2id 哈希。知道答案的人也能重置密码；找回尝试有短时限速，不影响正常密码登录。
- 没有预先设置密保，或同时忘记密码和密保答案时，不能通过此入口找回。密保并非强制启用。

### 页面调整与依赖修复

- 窄屏下“登录安全”与“数据与备份”并排显示，不再单独占满一行。
- 删除 AI 连接页与连接操作无关的工具数量说明。
- 将间接依赖 `fast-uri` 从 3.1.5 更新到 3.1.6，修复依赖审计报告的 URI 解析问题，不改变 MCP 的使用方式。参见 [上游修复说明](https://github.com/fastify/fast-uri/releases/tag/v3.1.6)。

### 更新建议与已有数据

密码字符校验只作用于新设置的密码，不会修改旧密码或影响旧密码登录。

- **首次部署：**直接使用新版本，设置密码时即可看到规则说明，并按需选择密保。
- **想使用密保：**建议更新原服务，再到“设置 → 登录安全”补设，不需要创建新实例或重设现有密码。
- **登录正常、也不需要密保：**可以不为本次功能更新，继续使用原版本；考虑到本次同时包含依赖安全修复，建议在日常维护时更新，不必为了启用密保专门折腾。

本版本增加保存密保配置的数据库字段，启动时自动迁移，已有账号默认不启用密保。不增加必填环境变量，不改变 MCP 连接方式。网站 ZIP 不包含或覆盖密保配置；整卷快照会保留。选择更新时，可按 [部署与运维](DEPLOYMENT.md) 的步骤备份并更新原服务。

### 感谢反馈

感谢小红书网友 **「吃一根薯条」** 分享首次设置后无法登录的经历，并提醒其他用户注意密码输入法。这个反馈促成了本次字符校验、页面说明和错误提示的改进，让问题尽量在设置时被发现，而不是留到下一次登录。

## 2026-08-30 · 完成通知与一致性修复

这次更新的重点是：**用户提交或完成任务后，AI 可以及时知道并继续处理**。同时修复了备份恢复、重复任务、幂等与分页中的一组一致性问题。

感谢 **Galatea's Garden 的小机 D 和 ta 的人类小屿**根据实际使用体验提出修改建议。真实的使用反馈让这次更新不只停留在功能设想，而是回应一段关系里确实发生过的等待、审核与回应。

### 完成通知

#### 新增领域事件

Phosphene 现在会记录四类事件：

| 事件 | 发生时机 | AI 通常要做什么 |
| --- | --- | --- |
| `task.submitted` | 用户提交需要 AI 审核的任务 | 查询证据并批准或驳回 |
| `task.completed` | 自助任务完成，或 AI 审核通过 | 回应完成结果 |
| `redemption.created` | 用户兑换奖励 | 查询并履行兑换 |
| `notification.test` | 用户测试通知配置 | 确认接收链路可用 |

事件先与任务、积分或兑换结果一起写入 SQLite。即使外部接收端暂时离线，完成事实也仍然存在。

#### 两种接收方式

- **Webhook**：适合有公网回调地址的 AI 宿主。网站可以配置订阅、轮换签名密钥、发送测试、查看投递状态和重新发送失败事件。
- **事件轮询**：适合 Codex Desktop 等没有固定回调入口、但可以定时运行的宿主。AI 调用 `query_history(kind="events")`，保存 `next_sequence` 后继续读取。

两种方式读取同一组领域事件。完整配置见 [完成通知](WEBHOOKS.md)。

#### 可靠投递

Webhook 使用事务 outbox 与进程内 worker：

- 只有 HTTP 2xx 视为成功
- 网络错误、超时与非 2xx 会按退避计划重试
- 最多尝试 12 次，之后进入停止重试状态
- 修复接收端后可从设置页重新排队
- 每个请求都有稳定 event id，接收端可据此去重
- HMAC-SHA256 签名密钥与 AI Token 分开管理

### 任务与积分行为修正

- AI 驳回提交时必须给出具体理由；用户可以看到理由并基于上次文字重新提交。
- 暂停每日重复任务会立即移除当天尚未提交的实例，但不会撤销已经提交、完成或进入历史的任务。
- 截止时间与揭晓时间现在会在创建和批量修改时校验，不再静默接受矛盾时间。
- AI 主动判定失败会遵守用户的惩罚暂停设置，并与手动 AI 扣分共用每日上限。
- 同一个幂等键只有在操作和请求内容都相同时才能重试；用旧键发送不同内容会明确报错。
- 任务与历史页会继续读取服务端分页，不再只显示前 100 项。
- 没有变化的 reconciliation 不再反复删除和重建派生统计。

### 备份与恢复

网站 ZIP 格式升级为 version 3：

- 新增领域事件与 Webhook 投递历史
- 保留幂等记录
- 数据库表从同一事务快照导出
- ZIP 以流式方式生成，恢复上传先写入磁盘
- 图片、对象路径、大小、哈希、格式和像素都会验证
- 数据替换、seed、reconciliation 与恢复审计在同一事务内提交
- 支持在仍保留现有图片的实例中就地恢复

恢复不会覆盖目标实例当前的登录密码、AI Token、Webhook 地址、订阅或签名密钥。version 1 和 version 2 备份仍可导入。

### 升级现有实例

1. 先创建 `/data` 卷快照，并从网站下载一份 ZIP。
2. 部署新版本；数据库 migration 会自动运行。
3. 检查网站登录、历史图片与 MCP `get_overview`。
4. 若要使用完成通知，在“设置 → 完成通知”中选择 Webhook；没有回调入口时，让 AI 使用事件轮询。

这次更新没有新增必填环境变量，也不会改变现有 AI Token。新实例默认不启用 Webhook，只有用户保存并启用配置后才会对外发送通知。

migration 不会为升级前已经完成的任务或兑换倒推生成事件；事件流从升级后新发生的动作开始。
